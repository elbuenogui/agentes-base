## Objetivo
Validar se a API da OpenAI produz transcrição de qualidade suficiente para entrevistas em
português brasileiro, construindo primeiro o motor mínimo (áudio → API → transcrição) antes de
qualquer camada de persistência, IA adicional ou multi-dispositivo.

## Escopo
- Dentro:
  - estrutura inicial do projeto em `transcritor/` (`backend/`, `frontend/`, `.env`,
    `requirements.txt`, `README.md`);
  - preenchimento dos placeholders `<...>` nos arquivos do kit (`CLAUDE.md` e demais) com o
    contexto deste projeto;
  - proteção de `transcritor/.env` no controle de versão;
  - backend que recebe áudio, guarda a API key exclusivamente no servidor e chama a API da
    OpenAI;
  - upload de arquivo de áudio existente (`.m4a`, `.wav`, `.mp3`);
  - gravação de áudio pelo navegador, com seleção do dispositivo de entrada;
  - seleção do modelo de transcrição (GPT-4o Transcribe, GPT-4o mini Transcribe, GPT-4o
    Transcribe Diarize);
  - exibição da transcrição na tela;
  - benchmark comparativo entre os três modelos no mesmo áudio (qualidade e custo).
- Fora (explícito): login, banco de dados, histórico, RAG, embeddings, busca semântica, análise
  qualitativa, resumo automático, múltiplos agentes, integração com smartwatch, transcrição em
  tempo real, app Android nativo, sincronização entre dispositivos. `README.md` da raiz do
  repositório (documentação do kit agentes-base) não é alterado — o projeto tem seu próprio
  README em `transcritor/README.md`.
